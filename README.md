# LLM-Based Strategic Mission Planning and Autonomous Flight Simulation with A* Algorithm

## Project Overview
I developed an autonomous flight simulation pipeline that uses a Large Language Model (LLM) as a strategic decision-maker. By analyzing natural language mission briefings, the LLM extracts optimal flight parameters. These parameters directly guide an A* path planning algorithm and a JSBSim-based flight dynamics engine, effectively bridging high-level human intent with low-level autonomous execution.

## Technology Stack
* **Core Language:** Python
* **Strategic AI:** Ollama Framework, Google Gemma3:4b
* **Flight Engine:** JSBSim
* **Navigation:** A* Algorithm (Geodesic)
* **Data Visualization:** Matplotlib, NumPy

## System Architecture
The project follows a modular pipeline, translating strategic context into physical flight maneuvers step-by-step. 

![System State Flow Diagram](images/state_flow_diagram.png)

### 1. Strategic Decision Making (LLM)
I utilized the Gemma3:4b LLM via Ollama to act as the cognitive layer. The model processes text-based mission briefs and evaluates the mission's urgency and danger. It then outputs strict numerical constraints, such as safety distances and maneuverability factors (turn penalties).

![LLM Strategic Decision Example](images/example_2.png)

### 2. Path Planning (A* Algorithm)
Constrained by the LLM's outputs, I implemented an A* algorithm to calculate the safest and most efficient route. This planner evaluates geodesic coordinates and actively applies turn penalties to ensure the plotted path respects the aircraft's aerodynamic limits.

![A* Algorithm Grid Logic](images/a_star_logic.png)
![Path Planner Map View](images/a_star_changing_path.png)

### 3. Flight Execution (JSBSim)
I integrated JSBSim to simulate the actual flight physics. The engine seamlessly transitions through operational phases—takeoff, waypoint navigation, and descent—handling real-time control adjustments to track the high-precision waypoints generated by the A* planner.

![Simulation and Flight Dynamics Results](images/result_1.png)

### 4. Data Visualization
To validate the system, I used Matplotlib and NumPy to process post-flight data. I converted geographic LLA (Latitude, Longitude, Altitude) data into an ENU (East-North-Up) Cartesian system, allowing for a clear 3D visual comparison between the planned route and the executed flight path.

![3D Flight Path Visualization](images/visualization.png)

## Limitations and Future Work
To maintain a realistic engineering perspective, I acknowledge the following limitations in the current build:
* **Static Hazard Handling:** The path planner currently treats danger zones as fixed 2D circular boundaries rather than dynamic or moving 3D threats.
* **Autopilot Constraints:** While JSBSim provides highly accurate physics, the autopilot logic can exhibit inconsistencies during abrupt maneuvers or sudden flight phase transitions.
* **Inference Latency:** The system's responsiveness is bottlenecked by the local inference speed of the LLM, which could delay real-time mid-flight updates.
* **Coordinate Conversion:** The 3D visualization assumes local linearity. This is perfectly sufficient for regional flights but lacks the precision required for global-scale navigation.
